# Snapshot 승인형 실제 Claude 신고서 초안

상세 실증 기록은 로컬 산출물 `build/approved-llm-report/REPORT.md`에 있다(저장소 미포함).

기존 실제 Run 일괄 차단 및 코드 소유 합성 fixture 경로는 유지한다. 신규 경로는
검증된 입력을 서버에서 다시 읽어 비식별화한 **개별 요청 Snapshot**만 승인받는다.
기본값/브라우저 분류 플래그로 실제 데이터 전송을 허용하지 않는다.

## 사용 순서

1. 담당자 확인·근거 검토·인지 기록·신고 진행 결정.
2. `AI 초안 생성`: 원문을 전송하지 않고 정확한 직렬화 요청과 대상 서버를 미리 표시.
3. Word 사고 유형·사유를 명시적으로 선택하거나, 같은 사건의 저장 양식 재사용을 선택.
4. 요청 내용 확인 후 개별 승인 체크 → `승인하고 AI 작성`.
5. 실제 HTTP 200 및 모델·출력 검증 성공 → 새 ReportDraft → 원본 KISA Word 자동 기입.
6. `Word 다운로드`. 신고서 제출 준비와 동의 완료를 의미하지 않는다.

`대체 초안 작성`은 별도 버튼이다. 승인 실패는 409/422로 차단한다. 실제 호출 실패/출력
검증 실패는 명시적인 대체 작성 버전으로 남으며 AI 작성으로 표시하지 않는다.

## API

- `GET /human-workflow/alerts/{alert_id}/report-snapshot`: 읽기 전용 미리보기, 전송/동의 저장 없음.
- `POST .../report-snapshot-approvals`: 현재 `snapshot_sha256`, Workflow 버전, 명시적 boolean 승인,
  멱등 키를 받아 append-only 로컬 승인 기록 생성.
- `POST .../ai-report-drafts`: `consent_id`, 현재 버전, 멱등 키. 선택적 `word_inputs` 또는
  `reuse_form_id`로 문서까지 준비한다. 기관·신고자 입력은 로컬 Word에만 사용한다.

스냅샷은 전체 로컬 입력 해시, 정책, Workflow 버전, 외부 목적지, 모델,
응답 모델 정책, 시스템 프롬프트, 토큰 상한, **실제 직렬화 요청 본문**에 결합한다.
내용이나 Workflow가 바뀌면 다시 미리보기·승인이 필요하다.
로컬 데모 담당자 경계·동일 Origin·루프백 제한을 유지한다. 실제 인증/운영 승인 시스템은 아니다.

## 공개 경계

현재 지원은 원본 검증과 추출기 재검증을 통과한 PowerShell 인코딩 옵션 사용 및
스크립트 인터프리터 외부 주소 연결 관측이다. 1~8개, 기여 Evidence 전체의 검증이 필요하다.
원본 ID·시각·명령줄·주소·계정·조직정보·원문/해시/참조 체인은 외부 본문에 넣지 않는다.
외부 참조는 요청 로컬 `O1`, `O2` 등이다. 원본과의 대응은 로컬 원장에만 보존한다.

자유로운 사실 추론을 허용하지 않는다. Claude가 제한된 한국어 표현을 구성하고,
허용된 행위 술어·접두/종결 표현·참조·미확인 문장이 모두 일치해야 통과한다.
사고 발생 시각, 원인, 감염, 유출, 피해 규모, 대응조치, 법적 판단은 임의 생성하지 않는다.
원본 양식, 기존 초안, 담당자 동의를 덮어쓰거나 자동 선택하지 않는다.

## 로컬 시연

이번 격리 Dashboard: `http://127.0.0.1:8816/dashboard`.
기존 8815는 Python 프로세스를 재시작하지 않았으므로 신규 API를 제공하지 않는다.
8815에서 신규 버튼을 눌러 404가 나면 차단 상태를 표시하고 별도의 대체 작성만 가능하다.
기존 서비스를 재시작해 신규 API를 반영하는 작업은 별도 승인 대상으로 남긴다.
