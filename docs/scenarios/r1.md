# R1 Scenario — Remote Administration Pairs

> **상태: 초안(Draft).** 역할 4가 소유하며, 역할 2·3·5의 검토를 받아 확정한다.
>
> 상위 정본은 `통합 표준안 3.0` §7-2, 데이터 계약은 `docs/data-contract-v0.2.md` 를 따른다.
> 이 문서는 R1 의 행위·Pair 설계·Ground Truth 규칙만 정의하며, 평가식이나 Contract 필드를
> 재정의하지 않는다.

> **현재 범위는 R1-V02 한 가지다.** 다른 R1 Pair 는 설계가 확정되는 대로 절을 추가한다.

## 1. R1 공통 전제

issue #72 에 정리된 값 가운데 R1-V02 에 필요한 것만 옮긴다. 출처 문서(통합 표준안, PoC
가이드)는 저장소 밖에 있다.

| 항목 | 값 |
| --- | --- |
| `gate_type` | `feasibility` |
| `ambiguity_required` | `true` — 초기 telemetry 중첩 필수 |
| `expected_overlap` | `powershell_execution`, `remote_session` |
| `expected_divergence` | `credential_access`, `lateral_movement`, `abnormal_process_lineage` |
| `entity_id` | Endpoint Host. Evidence 는 Source Event 가 관측된 host 에 귀속 (D-01, `data-contract-v0.2.md` §5-4) |
| host 구성 | Controller → Target-A. 필요하면 내부 연결 대상 Target-B |
| 네트워크 | Internal / Host-only. **인터넷 연결 없음** |

**S0 의 외부 연결 승인과 무관하다.** S0 는 issue #71 에서 제한된 NAT 예외(방식 A)를 다루지만,
R1-V02 는 내부망 안에서만 동작하므로 그 승인값을 쓰지 않는다.

### 하지 않는 것

```text
현재 단계에서 R1-V02 결과로 탐지 성능을 주장하지 않는다
성능 수치(탐지율, TTSD, FPR 등)를 이 문서에 적지 않는다
계보 Evidence 가 정의되기 전에는 Evidence·Score 경로를 검증 대상으로 삼지 않는다
```

**현재 단계에서 확인할 수 있는 것은 telemetry 생성 여부까지다.** 이유는 §8 과 §10 에 있다.

## 2. R1-V02 원격 프로세스 계보 — 목적과 범위

| 항목 | 값 |
| --- | --- |
| `scenario_id` | `R1` |
| `variation_id` | `V02` |
| 분기 축 | `abnormal_process_lineage` |
| 관측 host | **Target-A 하나** |
| 필요한 Sysmon EventID | 1, 3 |
| 추가 로그 채널 | 없음 |
| 규모 | Normal 1회 + Attack 1회 (Pilot) |

**검증 목적** — 새 로그 채널 없이 **프로세스 계보만으로** Normal 과 Attack 이 갈리는지
확인한다. 두 Run 은 같은 원격 세션과 같은 최종 관리 도구를 쓰고, 그 도구가 원격 세션 host
프로세스의 직접 자식인지(Normal), 중간 프로세스를 거쳤는지(Attack)만 다르다.

**이 Pair 를 먼저 다루는 이유**

- 현재 Sysmon 설정(`configs/sysmon/sysmonconfig-sample-v0.1.xml`)이 기록하는 EID 1·3 만 쓴다
- 현재 normalizer 가 처리하는 `process_create` · `network_connection` 만 쓴다
- 관측 host 가 하나라 `RunMetadata.target_host` 단일값과 맞고, 다중 host 축약 규칙이 필요 없다

## 3. Target-A 기준 관측 구조

```text
Controller                        Target-A (관측 host)                  Target-B
    |                                  |                                   |
    |--- 원격 세션 수립 (WinRM) ------>| 원격 세션 host 프로세스 생성        |
    |                                  |   Normal : host -> 관리 도구       |
    |                                  |   Attack : host -> 중간 -> 관리 도구 |
    |                                  |--- 내부 연결 (t+8) --------------->|
```

- Evidence 는 Target-A 의 Source Event 에만 귀속한다
- Controller 와 Target-B 에서 telemetry 를 수집하더라도 **별도 entity** 로 다루고 Target-A 와 합치지 않는다
- 원격 세션 host 프로세스 이름은 `wsmprovhost.exe` 로 **가정**하며, 실제 이름은 rehearsal telemetry 로 확인한다
- WinRM 목적 포트는 `TBD` (§11)

## 4. 행위 목록

`t+분` 은 설계상 상대 시간이다. 실제 기록은 `execution_record` 의 실행 시각이 정본이다.

### 4-1. 공통 구간과 최초 분기

| 시각 | Normal | Attack | 성격 |
| --- | --- | --- | --- |
| t+0 | Controller → Target-A 원격 세션 수립 | 동일 | **중첩** |
| t+2 | 원격 세션 host 가 승인 관리 도구를 직접 실행 (계보 깊이 2) | 동일 | **중첩** |
| t+5 | 관리 도구가 로컬 결과 파일 기록 | 원격 세션 host → **중간 프로세스** → 관리 도구 (깊이 3 이상) | **최초 분기** |
| t+8 | 관리 도구가 내부 대상에 조회 연결 | 깊이 3 이상의 프로세스가 Target-B 로 내부 연결 | 분기(연결 주체) |
| t+10 | 세션 종료 | 세션 종료 | 중첩 |

**공통 구간은 t+0 ~ t+5 직전까지다.** 최초 분기는 t+5 이다.

**Normal 도 t+8 에 내부 연결을 만든다.** 연결 자체가 아니라 **연결을 만든 프로세스의 계보**가
차이여야 한다. 연결 유무가 답이 되면 hard negative 가 성립하지 않는다.

관리 도구와 중간 프로세스는 **무해한 승인 도구**로 한정하며 구체 선정은 `TBD` 다. 이 문서는
명령·도구 이름·페이로드를 적지 않는다.

### 4-2. reference action

최초 공통 행위(t+0 원격 세션 수립)를 기준으로 하는 것을 제안한다. `reference_time` 은 그
행위가 Target-A 에 남긴 최초 telemetry 시각이다. 확정은 `TBD` (§11).

## 5. 예상 telemetry

### 5-1. Sysmon EventID

| host | EventID | 기대 내용 | 현재 Sysmon 설정으로 나오는가 |
| --- | --- | --- | --- |
| Target-A | **1** ProcessCreate | 원격 세션 host → (중간) → 관리 도구 | 예 |
| Target-A | **3** NetworkConnect | t+8 내부 연결. Normal 과 Attack 의 연결 주체 `Image` 가 다름 | 예 |

추가 Sysmon 설정 변경은 필요 없다.

### 5-2. 현재 계약으로 확인할 수 있는 것 — `parent_name`

`normalize_sysmon_process_create` 는 EID 1 의 `ParentImage` 를 `process.parent_name` 으로
옮긴다(`src/incident_awareness/normalization/sysmon.py`). 따라서 **t+5 에서 관리 도구의 직접
부모가 원격 세션 host 인지 여부는 현재 event_v0 로 판정할 수 있다.**

```text
Normal   관리 도구  process.parent_name = <원격 세션 host>
Attack   관리 도구  process.parent_name = <중간 프로세스>
```

### 5-3. 현재 계약으로 확인할 수 없는 것 — 계보 깊이와 EID 1 → 3 연결

`ProcessInfo`(`src/incident_awareness/common/models/event.py`)는 `pid`, `name`, `path`,
`command_line`, `parent_pid`, `parent_name` 만 갖고 `extra="forbid"` 다. ProcessGuid 계열
필드가 없다.

| 확인하려는 것 | 필요한 연결 | 현재 |
| --- | --- | --- |
| 계보 깊이 3 이상 | 조부모 이상의 체인 | **불가** — 한 단계 부모 이름만 표현된다 |
| t+8 연결을 만든 프로세스의 계보 | EID 3 과 EID 1 의 결합 | **불가** — 아래 참조 |

Sysmon EID 3 원천에는 `ParentImage` 가 없다(`samples/raw/sysmon-0001.jsonl` 로 확인). 그래서
정규화된 `network_connection` 의 `process.parent_name` 은 항상 `null` 이다. 연결 주체의 계보를
알려면 EID 3 의 `ProcessGuid` 로 EID 1 을 찾아야 하는데, 그 값이 event_v0 에 남지 않는다.
`parent_pid` 로 잇는 방법은 PID 가 재사용될 수 있어 신뢰하지 않는다.

**결과적으로 현재 계약으로 가능한 R1-V02 는 "한 단계 부모 이름" 으로만 갈리는 약한 형태다.**
§7 의 변형처럼 Normal 에도 승인 wrapper 를 넣으면 한 단계 부모만으로는 구분이 사라진다.

## 6. Ground Truth

`data-contract-v0.2.md` 의 RunMetadata · ExecutionRecord 경계를 따른다. R1-V02 에서 추가로
남길 항목은 다음과 같다.

| 항목 | 기록 위치 |
| --- | --- |
| `scenario_id` · `variation_id` · `run_id` · `run_type` · 반복 번호 | RunMetadata |
| 행위별 실행 시각 | `execution_record.csv` |
| reference action 과 `reference_time` · `reference_source_event_id` | RunMetadata |
| 최초 분기 action | 이 문서의 행위 표 |
| 단계별 프로세스 이름 · 경로 · ProcessGuid · ParentProcessGuid | 실행 기록(원천 telemetry 에서 추출) |
| 계보 깊이 (Normal 2 / Attack 3 이상) | 실행 기록 |
| t+8 연결을 만든 프로세스의 계보 위치 | 실행 기록 |
| Sysmon config version · hash | RunMetadata · Manifest |
| snapshot 이름과 복원 확인 | RunMetadata(`vm_snapshot`) · 실행 기록 |

`ExecutionRecordRow` 에는 host 필드가 없다(issue #72 질문 7). R1-V02 는 관측 host 가
Target-A 하나이므로 행위 표와 `action_id` 로 충분하다고 보고 ExecutionRecord 계약을 바꾸지 않는다.

ProcessGuid 는 event_v0 에 들어오지 않으므로 **원천 telemetry 에서 뽑아 실행 기록으로만**
보관한다. Ground Truth 는 런타임 입력이 아니므로 이 값이 Evidence 나 Fusion 에 흘러가지 않는다.

## 7. hard negative 와 변형 축

**Normal 은 idle 이 아니다.** 같은 원격 세션을 열고, 같은 관리 도구를 실행하고, 내부 연결까지
만든다. Attack 과 다른 것은 계보 구조뿐이다.

| 축 | 변형 | 비고 |
| --- | --- | --- |
| 계보 깊이 | 3단계 / 4단계 | 깊이 자체가 정답이 되지 않도록 Normal 에도 승인 wrapper 변형 검토 |
| 중간 프로세스 종류 | 스크립트 해석기 / 승인 wrapper | 구체 선정 `TBD` |
| 분기 시각 | t+5 / t+9 | Fusion window 보다 충분히 넓게 |
| 연결 대상 | Target-B / 내부 파일 서버 | 실험망 CIDR 필수(`TBD`) |

**Shortcut 통제** — 프로세스·파일 이름에 `attack_`·`normal_` 같은 prefix 를 두지 않는다. 계정,
작업 디렉터리, 행위 수는 두 Run 에서 같게 한다.

## 8. 성공 · 실패 판정

**이 판정은 telemetry 수집 품질에 대한 것이다.** 탐지 성능 판정이 아니다.

| 구분 | 기준 |
| --- | --- |
| 성공 | ① 두 Run 의 t+0 ~ t+2 계보가 같다 ② Attack 의 t+5 관리 도구 `parent_name` 이 원격 세션 host 가 아니다 ③ 두 Run 모두 t+8 EID 3 이 있다 ④ 원천 telemetry 에서 ProcessGuid 체인이 끊기지 않는다 |
| 실패 | 계보 중간 EID 1 누락 / Normal 과 Attack 의 t+5 부모가 같음 / EID 3 0건 |
| 무효 | snapshot 미복원 상태 실행 / 같은 `run_id` 재사용 / 승인되지 않은 도구 사용 |

## 9. 안전 조건

- 격리된 Controller · Target VM 과 복원 가능한 snapshot 에서만 실행한다
- Internal / Host-only 네트워크만 쓴다. 공인 인터넷 연결은 없다
- 실제 운영 계정 · 운영 호스트를 쓰지 않는다
- 관리 도구와 중간 프로세스는 무해한 승인 도구로 한정한다
- 자격증명 접근 · 덤프 · 로그 삭제 · 권한 변경은 이 Pair 에 포함하지 않는다
- 추가 승인은 필요 없다. 다만 도구 선정(`TBD`)은 실행 전에 확정한다
